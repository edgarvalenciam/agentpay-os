# Revisión AgentPay OS v1.2 — 2026-11-07

## Evaluación

El flujo local está implementado hasta G6: core determinista, API con identidad por actor, snapshots/consentimiento, reservas, idempotencia, pagos mock, conciliación, inventario, outbox/bandeja de comercio, agente de propuestas y frontend. El modelo no puede aprobar ni pagar. Los diagnósticos bancarios QR/Push y un caso OpenAI real ya se verificaron en sesiones anteriores; esta revisión no los repitió. G7 y la integración comercial real no se declaran aprobados.

Revisión focalizada de las fronteras core/API/DB/adaptadores/BFF/cliente y su suite, seguida de regresiones y recorrido de navegador. No equivale a auditoría externa de seguridad o validación de producción.

## Mejoras aplicadas

| Hallazgo | Cambio y evidencia |
|---|---|
| Cambiar una propuesta dejaba su stock reservado hasta vencer | Nueva liberación autenticada/idempotente de propuestas sin aprobar. Comprueba propiedad y ausencia de orden; no borra evidencia. Serializada con aprobación; solo una puede ganar. La UI espera el acuse antes de permitir editar. |
| Red interrumpida antes del acuse podía dejar la pantalla sin recuperación | Botón explícito Recuperar la misma solicitud: consulta primero; si no hay intento, usa exactamente la clave/cuerpo originales. Un intento existente/UNKNOWN nunca se reenvía al proveedor. No hay reintento automático. |
| Almacenamiento del navegador bloqueado impedía continuar | Conserva estado en memoria y avisa mantener la pestaña abierta; no promete recuperación tras cerrar. |
| Verificaciones de sesión/perfil podían ser inconsistentes | Bootstrap admite query string sin omitir protección de otras rutas; BFF exige salud 200 y banderas explícitas mock=true/real=false/fixture. |
| Roadmap y encabezados seguían describiendo fases terminadas como pendientes | Estado global, arquitectura, matriz pey, AGENTS, README y contratos sincronizados con evidencia, manteniendo separados historial y alcance vigente. |
